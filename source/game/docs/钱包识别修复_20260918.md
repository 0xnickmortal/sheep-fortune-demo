# 手机钱包重复识别修复（2026-09-18）

问题：OKX App 中同时出现两个 OKX Wallet；Binance Wallet 中同时出现 Binance Wallet 与 MetaMask。

原实现同时收集 EIP-6963、钱包专属命名空间和 `window.ethereum`，只按对象引用去重。同一钱包的不同包装对象会重复显示；仅凭 `isMetaMask` 就命名为 MetaMask 也不可靠。MetaMask 官方明确说明其他钱包也可能设置该兼容标记。

## 本次处理

- 优先使用 EIP-6963 提供的钱包身份和接口。同一对象或会话 UUID 的重复广播不会增加入口，也不会替换已经记录的接口。
- OKX、Binance 等已识别钱包的旧接口作为补充；同品牌已由 EIP-6963 提供时不重复列出旧接口。
- 已有明确身份的钱包时，不再把通用 `window.ethereum` 包装接口当成另一个钱包。无法识别身份的旧接口显示“浏览器钱包”，不会仅凭 `isMetaMask` 冒认 MetaMask。
- 真正独立的钱包仍可分别选择；不同 EIP-6963 会话不会因为显示名称相同就被合并。
- 已选钱包不会因延迟广播而在会话中被自动替换。断开连接、账户签名校验、BSC检查与余额读取继续使用所选接口。
- 钱包身份只用于界面和接口选择，不用于管理员权限、白名单或资金授权。

## 验证

- 钱包发现、BSC切链、账户隔离和持币读取共27项测试通过。
- 390×844 浏览器模拟 OKX/Binance 的独立广播接口和兼容包装对象：各显示一个正确入口，完成本地EVM账户签名登录，签名未调用兼容别名接口，无横向溢出或脚本错误。OKX断开后仍只显示一个入口。
- 单元测试覆盖多钱包并存、延迟广播、重复UUID、未识别接口与取消登录。
- 此处为接口模拟与本地EVM验证，未在真实手机 App 内直接操作；用户需关闭旧页面并重新打开线上页面检查。构建自动更新全部前端模块的缓存版本。
- 本次不修改现有4个白名单的开放范围、游戏经济参数或托管合约。
