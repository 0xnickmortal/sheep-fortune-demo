# 钱包白名单

白名单按 BSC 钱包地址与当前代币分别配置。登录必须先完成钱包签名；只连接钱包、提交一个地址或修改浏览器参数都不能获得资格。

## 配置方法

1. 在带后端的游戏域名打开 `/admin/whitelist/`，使用服务端的 `OPS_AUTH_KEY` 登录。
2. 填写钱包地址与九档概率：0、0.5、1、1.2、1.5、2、3、5、10 倍，合计100%，最多两位小数。
3. 勾选启用后保存。新增地址默认停用，默认显示普通77%概率，管理员需要自行确认专属概率。
4. 用户签名登录后自动应用。玩法页公布当前钱包实际使用的概率，账户页显示白名单身份与免提现手续费资格。
5. 修改名单时用“编辑”，停用后新局恢复普通概率。旧页面下注前会收到规则更新提示。

管理密钥不写进网页、不存浏览器本地存储。页面关闭后需要重新输入。管理员接口独立鉴权，游戏登录不等于管理权限。

## 接口与版本

- `GET /api/admin/whitelist`：读取当前代币的白名单，每页最多100个地址，使用 `after` 游标读取下一页。
- `POST /api/admin/whitelist`：新增、修改或停用；必须带 `Authorization: Bearer <OPS_AUTH_KEY>` 和唯一 `Idempotency-Key`。
- 请求字段：`address`、`weights`、`enabled`、`revision`。`weights` 按上述九档顺序，每个数值为概率百分比乘100，合计10000；新增 `revision=0`，编辑使用读取时的版本。
- 白名单规则不能改变倍率、下注上限、奖池预留、转盘手续费、金元宝规则或正式付款开关。
- 配置保存留有操作记录。规则与提现费率各有版本，管理员并发编辑会报冲突，不覆盖其他人刚保存的配置。
- 开奖使用后端独立随机抽样，不按上一局的盈亏动态改变概率。

## 提现口径

白名单的游戏提现手续费固定为0；报价、冻结申请和记录均保存对应豁免版本。名单后来停用，不重算已经提交的提现。

当前普通钱包的提现费率也仍为0；本次没有启用之前讨论的盈利提现5%。免游戏提现手续费不代表代币转账税、链上Gas也消失。

## 资金与历史保护

每一局保存专属规则快照；扣款与名单版本校验在同一个事务内执行。配置在结算过程中变化会回滚并要求刷新，已经成功的重复请求返回原结果。普通钱包和测试账户不会继承其他地址的专属规则。历史局、金元宝和余额不会因名单变更而重算。

## 部署

后端数据库新增迁移 `0003_left_night_thrasher.sql`，通过现有 Drizzle 迁移流程部署。服务端构建使用 `npm run build`。GitHub Pages 的静态试玩构建只使用普通规则，不承载钱包鉴权、管理接口或真实提现。

名单初始为空。实际白名单地址及各自专属概率尚待填写；正式充值提现仍受原有上线开关和支付配置限制。

验证：后端覆盖签名身份、概率枚举、伪造地址、管理员权限、配置并发、游戏/提现幂等、停用与历史快照、账本守恒；测试钱包和测试账本不涉及真实代币。
