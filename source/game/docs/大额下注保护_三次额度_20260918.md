# 大额下注保护与下一局补偿（每钱包累计3次）

状态：按每个钱包累计最多3次的要求实现；发布时保持仅原有4个钱包可进行资金操作，公开充提仍关闭。`BET_PROTECTION_ENABLED` 缺省或为 `false` 时不应用保护；生产配置启用此规则。发布记录见文末。

## 本次具体解释

- “50%以上”解释为大于等于50%。分母是下注前的游戏可用代币余额，加历史待领取奖励；不包含钱包链上持币、金元宝或正在提现的锁定余额。这里只判断金额比例，无法判断玩家是否真的在梭哈。
- 满足大额条件且没有待补偿时，移除0倍权重，其他现有权重按比例归一化。这是当前实现的分配方式，并非唯一可行方式。
- 每个钱包累计最多3次补偿，不按天重置。额度未用完时，大额局中0.5倍后记录本局损失；普通小额局中的0.5倍不生成补偿。成功结算补偿才计1次，达到10倍仍未补齐也计1次。充值、重连和服务重启均不重置次数；不追溯旧局。额度用完后仍保留大额局不出0倍，但不再产生新补偿。
- 下一次成功下注优先结算这笔补偿，按新下注金额，选择“扣费后净盈利足够覆盖原损失”的最小现有倍率。采用现有倍率档位，不创造新档位；上限10倍，达到上限仍有差额的只执行这一次，差额不延续。
- 补偿局优先于新的大额判定，不叠加第二笔补偿。失败请求、余额不足和奖池不足不消耗资格；重复请求只结算一次。重连、服务重启和开关暂时关闭均保留已记录的待补偿。
- 正常的大于1倍手续费、9.3%销毁、15%/5%推荐返佣和金元宝规则维持现状。金元宝没有因为后续补回亏损而撤销。
- 白名单仍先采用各自基础权重，然后应用同一保护规则；若白名单100%是0倍，配置冲突会拒绝下注，不自动改成另一个未约定的基础分布。补偿在所有已列出且不超过10倍的盈利档位中选择，包含基础权重为0的档位。
- 客户端不能指定是否获得保护、损失额或开奖结果。服务端以账户和规则快照判定，并与扣款、返奖、推荐奖励、金元宝在同一个数据库事务中记录。
- 启用后公开规则版本变化，不再把77%标为整个动态模型的净返还率。玩法、结果和账户页分别展示适用规则、已补回/上限差额、待补偿额与已用/剩余次数。

## 例子中的5倍不足以回本

1万余额，第一局下注5,000中0.5倍，损失2,500，余额7,500。

第二局下注500，若给5倍：返还2,500，手续费25，实际入账2,475；该局净赚1,975，最终余额9,475，仍亏525。

在现有档位中给10倍：实际入账4,975；该局净赚4,475，最终余额1.1975万，比初始余额多1,975。

## 精确模型分析

分析脚本：`node scripts/analyze-bet-protection.mjs`。输出到 `outputs/bet-protection/analysis.json` 和 `scenarios.csv`。采用完整枚举，不存在随机样本误差。

| 项目 | 结果 |
|---|---:|
| 当前基础表净返还期望 | 77% |
| 大额局移除0倍并归一化后（尚无后续补偿） | 106.9444% |
| 例子策略的净返还期望（下注5,000；仅中0.5倍后下注500补偿） | 128.6043% |
| 同策略奖池留存，扣9.3%销毁，无推荐返佣 | -37.9043% |
| 同策略奖池留存，扣9.3%销毁及两级20%返佣 | -57.9043% |
| 同策略平均额外发放金元宝 | 625 |

这些是特定下注策略的期望，不是全部玩家的统一期望，不计金元宝兑换。例子中的完整一轮或两轮组合没有亏损结果：1倍保本，其他所有分支盈利。3次额度限制了同一钱包能使用这种补偿的次数，但不能据此得出整个模型奖池正留存；钱包额度也不等同于每个自然人的额度。“移除0倍并确保补回亏损”不能同时保证奖池正留存；即使后续压低大额局的高倍权重，这个补回机制仍会消除满足条件的组合亏损，并留下手续费以外的销毁、返佣成本。

## 触发频率

普通表中0倍28%、0.5倍18%。大额局移除0倍后，0.5倍的实际权重占比为18/72=25%，约四次符合条件的抽取中一次。5次符合条件且独立的抽取至少触发一次为76.27%，10次为94.37%。此计算不包含确定性补偿局，也不代表所有玩家都会触发25%；白名单使用各自权重。

三次用完后，大额局不出0倍仍使该类单局净返还期望为106.9444%，尚未扣销毁和返佣。因此三次上限只能控制补偿次数，不能保证奖池增长。
