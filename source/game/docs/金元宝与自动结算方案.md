# 金元宝与自动结算方案

## 本期交付

每次转盘仍按固定概率抽一个倍率，概率不变。后台先结算并持久化，前端动画展示已保存的结果，动画结束后同步两种余额。金元宝是独立积分，不是代币本金的退款，也没有已确定的XAUT兑换价值。

| 投入1,000代币 | 自动返还代币 | 手续费 | 增加金元宝 |
| --- | ---: | ---: | ---: |
| 0× | 0 | 0 | 1,000 |
| 0.8× | 800 | 0 | 200 |
| 1× | 1,000 | 0 | 0 |
| 1.2× | 1,150 | 50 | 0 |
| 1.5× | 1,450 | 50 | 0 |
| 10× | 9,950 | 50 | 0 |

所有代币净返还立即进入可用余额，可以继续下注；提币才转到钱包。旧待领奖励在账户读取时自动归入余额，不重复扣费，不改变历史净奖励。金元宝从本期规则开始发放，不补发历史亏损。没有下注的充值不产生金元宝，手续费不产生金元宝；1×及以上不发金元宝。

## 页面与接口

- 首页显示代币余额、金元宝余额；结果区分别显示代币返还与金元宝增加。
- 底部三个入口为“玩游戏／金元宝／我的账户”。金元宝页展示获取记录；游戏记录移到我的账户。
- “去提币”沿用已有钱包提现流程，取消游戏奖励的手动领取步骤。
- 金元宝兑换入口显示“兑换暂未开放”，API同样拒绝兑换请求。
- GET /api/account：余额、金元宝、冻结余额、账户版本。
- POST /api/play：服务端计算代币、积分、手续费；同一个操作编号只结算一次。
- GET /api/ingots：当前账户金元宝、最近50条获取记录、兑换状态。
- POST /api/ingots/redeem：本期固定返回 REDEMPTION_CLOSED，不收取积分。

## 数据与核对

新增 accounts.ingots 和 rounds.ingots，默认0，不回填历史亏损。使用18位精度的整数字符串，业务计算使用BigInt。每局扣代币、返代币、发金元宝、写局记录和写账本在一个D1事务中提交；使用账户和奖池版本条件更新处理并发。

金元宝账本资产与代币账本资产分开。审计同时核对两种余额；金元宝不能用于代币下注或提现。旧奖励迁移使用精确加法和幂等操作，保留历史记录与已提交提现，不改变链上资金设置。

测试账户的金元宝仅供体验，不会合并到正式钱包账户，也不会用于真实资产兑换。本期没有开启正式充值、提现或XAUT转账。

## 下一期：资产兑换（待确定）

开放前需要确定：兑换资产及所在链、验证后的合约地址和精度、兑换比例是固定还是报价、最低兑换额、每日限额、手续费、储备资金来源与额度、测试积分政策。暂不设置任何兑换率或承诺兑换价值。

建议流程：服务器生成有有效期的报价并保存比例与费用快照；用户确认后原子冻结金元宝与对应资产储备；后台生成可审计的发放请求；实际转账确认后扣除冻结积分。转账结果不明确时保持冻结并查询同一笔交易，确认失败才退回，防止重复发放。可复用现有提现的签名匹配、交易哈希与幂等确认机制。

后续数据表应包含兑换报价、兑换订单、积分冻结余额、资产储备与发送记录。兑换接口仅接受服务器报价编号，不能信任客户端提供的兑换率、到账额或收款链。
