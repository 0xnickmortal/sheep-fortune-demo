## 历史四钱包验收机制（当前已关闭）

此前采用 `LIVE_PAYMENTS_ENABLED=false` 与 `PAYMENTS_VALIDATION_ENABLED=true`；服务端 secret `PAYMENTS_VALIDATION_WALLETS` 保存本次确认的钱包 JSON 数组，不进入前端或 Git。

非管理员必须同时满足：钱包签名登录有效、账户属于当前代币、地址在该固定名单中、D1 白名单仍启用。管理员原有操作权限保留。以后新增白名单不会自动加入本次开放名单；普通白名单身份也不授予管理员权限。错误或缺失的名单配置不会开放普通地址。

玩家刷新游戏页面并连接对应钱包后，从已验证账户获取充值、提现和下注权限。后台定期到账核对使用同样的账户范围；无登录的公开配置仍显示关闭。停用白名单会关闭该非管理员地址的新操作，尚未执行的链上提现凭证仍遵循原有有效期。

仅管理员可通过 `/api/admin/session` 核对固定名单。修改名单用 Wrangler 的 `secret put PAYMENTS_VALIDATION_WALLETS`，由标准输入提供 JSON；不要提交钱包名单文件、私钥或 OPS 密钥。

## 充值

“我的账户 → 充值”：输入币数，钱包确认精确额度授权（已有足够授权则跳过），再确认 `deposit`。按 `Deposited` 实际到账、正确代币/钱包/托管合约、至少20区块确认入账。普通直接转币不计为个人充值。

交易提交后保存交易哈希，登记后台待确认任务，网页每15秒核对，后台每分钟补充核对。刷新或重新打开可恢复；若本机存储丢失，可用自己的充值交易哈希核对。失败记录会说明原因，同一交易重复核对不会重复入账。链上RPC故障会保持待确认，不会伪造到账。

## 提现

“我的账户 → 提现”：输入数量，查看手续费与预计到账，确认冻结，再由钱包执行一次性提现凭证。当前普通提现手续费0，白名单提现也为0，没有擅自启用盈利提现5%。链上Gas由用户钱包支付。

凭证固定收款人、币数、BSC网络、托管地址、有效期与签名人版本；有效期1小时。无法冒用其他玩家凭证或转到别人的地址。重复提交不重复付款，冻结余额不能再次下注或提现。实际到账核对完成后自动清除冻结；未执行且确认过期/撤销的申请自动退回余额。钱包取消操作不立即解冻，避免仍有效的凭证被重复花费。

BSC公共节点可能关闭 `eth_getLogs`。程序根据托管合约记录的执行区块，找到页面发起的直接交易，再校验交易回执和事件；无需遍历历史日志。外部合约中继仍使用事件查询，因此运营如引入第三方中继需配置支持日志的RPC。

## 白名单与管理

玩家页面不提供运营管理入口。项目管理员通过独立管理地址签名登录；管理页提供奖池、充值和提现记录，白名单页可新增、编辑和停用地址。管理员地址由服务端 `ADMIN_WALLET` 决定，不能由前端请求伪造；管理员钱包更换时需同步更新此配置。

每个地址有9档概率，最多两位小数、合计100%；启用后新一局使用该配置，并免游戏提现手续费。停用恢复普通规则，已结算游戏与已申请提现保留原快照。客户端不决定中奖结果。编辑采用版本校验；不确定的保存重试复用原操作编号。

管理支持钱包会话（POST同源验证）或服务端OPS密钥。密钥仅用于备用，不能写入前端配置或Git。普通账户、其他代币账户和跨站请求不能执行管理写操作。退出会撤销服务端登录会话，旧Cookie不能重新进入后台。

## 奖池核对

`POOL_FUND_SYNC_ENABLED=true` 时，根据确认区块的累计 `totalFunded`，扣除已手动入账部分和自动入账检查点，仅入账增量；游戏税等 `directPoolIncome` 独立核对。重复任务或并发不重复增加奖池。用户充值不被计入可支出的游戏奖池。累计自动注资启用后拒绝再次按注资哈希重复入账。

`DEPOSIT_START_BLOCK=122584076` 是本次充值开放检查点，不是合约部署区块。设置前确认托管合约累计用户充值和提币均为0。已经完成的200万注资通过累计计数核对，不受该充值起始区块影响。

后台每次补充处理最多2笔待确认充值和2笔待完成提现，页面会同时核对自己的交易。该任务只读取链上信息和更新账本，不代替用户发送交易或花Gas。大量离线待处理任务可能排队；可用管理页主动核对。奖池读取失败不会阻止本轮充提核对尝试。
